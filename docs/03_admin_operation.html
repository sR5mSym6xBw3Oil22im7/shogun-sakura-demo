Operations

運用範囲

運用担当者は、公開URLの死活監視、Render環境変数の安全な管理、GitHub Pagesの公開状態、障害時の一次切り分けを担当します。注文データは一時保持であり、バックアップ対象ではありません。

Daily Check

日常確認

フロントエンド

トップページ、注文確認、注文完了、注文履歴の各画面が表示できることを確認します。

バックエンド

/api/health がHTTP 200と {"status":"ok"} を返すことを確認します。

AI案内

価格に関する代表質問へサイト掲載内容に沿った回答が返ることを確認します。

確認用コマンド

curl -i https://shogun-sakura-demo.onrender.com/api/health

curl -i -X POST https://shogun-sakura-demo.onrender.com/api/chat   -H 'Content-Type: application/json'   -d '{"message":"セットの価格はいくらですか？"}'
Environment Variables

環境変数管理

変数必須用途運用上の注意
GEMINI_API_KEY必須Gemini API認証リポジトリや画面へ記載しない。漏えい時は即時失効・再発行。
MCP_INTERNAL_TOKEN必須内部MCP認証十分に長いランダム値を使用し、定期的に更新。
MCP_BASE_URL必須MCP接続先通常はバックエンド自身の公開URL。末尾の /mcp は有無どちらも処理可能。
ALLOWED_ORIGINS必須CORS許可元本番は https://sr5msym6xbw3oil22im7.github.io を設定。
SITE_SOURCE_BASE_URL任意AI根拠ページのベースURL未設定時は公開フロントエンドURLを使用。
PORT自動待受ポートRenderが自動付与。ローカル既定値は8080。
Incident Response

障害時の一次切り分け

  1. 影響範囲を確認する画面全体、注文のみ、AIのみ、履歴のみのいずれかを特定します。
  2. ヘルスチェックを確認するHTTP 200でなければRenderのイベント・ログ・デプロイ状況を確認します。
  3. 環境変数を確認する値そのものを共有せず、設定有無、余分な空白、URL形式を確認します。
  4. CORSを確認するブラウザ開発者ツールでCORSエラーがある場合、ALLOWED_ORIGINS と公開元ドメインを一致させます。
  5. AI経路を確認する注文APIが正常でAIだけ失敗する場合、Geminiキー、MCP URL、内部トークン、サイト本文取得を順に確認します。
  6. 復旧後に代表操作を再確認するヘルスチェック、注文登録、履歴表示、AI質問を一巡します。
Data Lifecycle

データ初期化と保持

注文データはバックエンドプロセス内のH2メモリDBに保持されます。サービス再起動、再デプロイ、プロセス終了で全件初期化されます。個別削除APIは実装されていません。

意図的に初期化する場合：Render Web Serviceを再起動するか、新しいデプロイを実行します。実施前に、現在の注文履歴が失われることを関係者へ周知してください。
Periodic Maintenance

周期点検項目基準
週次公開画面、API、AI代表質問主要機能が一巡して正常
月次Renderログ、デプロイ履歴、エラー傾向継続的な5xxやタイムアウトがない

半年APIキーと内部トークンローテーションを実施
変更時許可ページ、CORS、公開URL設定とコードの整合性を確認
