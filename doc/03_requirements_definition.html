1. システム目的

桜の押し花と「将軍」の扇を組み合わせた商品セットを紹介し、デモ注文、注文履歴、AI案内を提供するポートフォリオWebアプリを構築する。

2. 業務要件

ID要件優先度
BR-01商品コンセプト、画像、価格、用途を一画面で確認できること。必須
BR-02利用者が注文フォームを入力し、確認画面へ進めること。必須
BR-03実在の個人情報をバックエンドへ送信せず、確認画面で生成した架空データを送信すること。必須
BR-04受け付けたデモ注文を同一稼働中の注文履歴として表示できること。必須
BR-05サイトに記載された内容だけを根拠にAIが回答すること。必須
BR-06実販売・決済・在庫引当を行わないこと。必須

3. 機能要件

ID機能要件受入条件
FR-01商品表示商品名、セット内容、税込デモ価格4,800円、商品画像を表示する。
FR-02注文入力氏名、メール、郵便番号、住所、数量、備考を入力できる。
FR-03入力検証必須、形式、文字数、数量範囲を画面側とAPI側の両方で検証する。
FR-04注文確認入力値のうち数量だけをsessionStorageで引き継ぎ、その他は架空データを生成して表示する。
FR-05注文登録POST /api/ordersで架空注文を登録し、成功時に完了画面へ遷移する。
FR-06注文履歴GET /api/ordersで登録順に一覧表示する。
FR-07AI案内500文字以内の質問をPOST /api/chatへ送り、回答を会話欄へ追加する。
FR-08ヘルスチェックGET /api/healthでstatus=okを返す。

4. 非機能要件の概要

  • 主要画面はPC・タブレット・スマートフォン幅で閲覧できる。
  • 公開環境はHTTPSを使用する。
  • APIキーと内部トークンは環境変数で管理する。
  • CORSは許可オリジンを限定する。
  • AI回答はサイト本文に限定し、秘密情報を出力しない。
  • コードをフロント、Controller、Service、Repository、DTO等に分離し保守性を確保する。

5. 制約条件

  • 商品はデモであり、実際の売買契約を成立させない。
  • 注文データはH2インメモリDBへ一時保存する。
  • ユーザー認証を実装しないため、注文履歴は公開デモデータとして扱う。
  • 外部AIサービス停止時は、価格質問への限定フォールバックまたは回答不能メッセージを返す。

6. 受入基準

  1. 公開URLでトップ画面が表示される。
  2. 有効な数量で注文確認画面へ進み、架空データを登録できる。
  3. 登録後、注文履歴画面に注文が表示される。
  4. 無効入力は登録されず、利用者にエラーを表示する。
  5. サイト外の質問や秘密情報要求に回答しない。
  6. ヘルスチェックが正常応答する。
