1. セキュリティ方針

実販売・認証を行わない公開デモであることを前提に、個人情報を送信しない設計、入力値検証、秘密情報の環境変数管理、外部連携先の制限を重点とする。

2. 対策一覧

脅威・課題対策実装箇所
実在個人情報の保存トップ入力値は確認画面へ渡さず、数量だけを保存。確認画面で架空データを生成。main.js / orderConfirmation.js
不正入力フロント検証＋Bean Validation＋DB CHECK制約。main.js / DTO / schema.sql
SQLインジェクションPreparedStatementのプレースホルダを使用。OrderRepository
XSS履歴・チャット表示はtextContentでDOMへ設定。orderhistory.js / chat.js
過剰なCORS/api/**の許可Originを設定値で限定。許可MethodはGET/POST/OPTIONS。CorsConfig
APIキー漏えいGEMINI_API_KEYを環境変数管理し、クライアントへ送らない。GeminiApiConfig
MCP不正利用内部トークン、Origin制限、GET拒否。McpAuthentication / MCP Config
SSRF・任意ページ取得ベースURLと固定ページのallowlist、redirect拒否。SiteContentService
プロンプトインジェクションサイト本文をデータとして扱い、外部知識・命令・秘密情報開示を禁止。chatbot-system-prompt.txt
秘密情報を含むAI回答禁止語を検査して回答を採用しない。ChatService
二重送信処理中に注文ボタンと遷移リンクを無効化。orderConfirmation.js

3. 秘密情報

情報保存場所公開禁止
Gemini APIキーRender環境変数／ローカル.envリポジトリ、HTML、ログ、APIレスポンス
MCP内部トークンRender環境変数／ローカル.envブラウザ、公開ドキュメントの実値
MCP接続先環境変数必要に応じて内部構成として扱う

4. 残存リスク

  • 認証がないため、公開APIの注文登録・履歴取得はデモ用途に限定する。
  • H2データは永続化されないが、稼働中は履歴画面から閲覧できるため架空データ以外を登録しない。
  • 外部AIサービスの可用性・レート制限は完全には制御できない。
  • CSPやレート制限は将来の本番化時に追加検討する。
