1. 作品概要

項目内容

  • 画面・API・DB・セキュリティ設計
  • HTML/CSS/JavaScript実装

  • 開発ドキュメント作成

3. 工夫点

工夫内容
個人情報保護注文入力の氏名等を送信せず、数量だけを引き継いで架空データを生成する。
二重検証フロントとAPIの両方で必須、形式、文字数、範囲を検証する。
AIの根拠限定固定許可ページだけを取得し、一般知識や秘密情報への回答を禁止する。
障害耐性Gemini停止時も価格質問への限定フォールバックを用意する。
内部連携保護MCPに内部トークン、Origin制限、GET拒否を実装する。
環境分離GitHub PagesとRenderを分離し、CORSと環境変数で接続する。
テストRepository、Service、Controller、MCP、ブラウザ操作まで36ケースを設計する。

4. 使用技術

  • HTML5 / CSS3 / Vanilla JavaScript
  • Java 21 / Spring Boot 3.3.5
  • Spring JDBC / H2
  • Gemini API / Model Context Protocol SDK
  • jsoup
  • JUnit / Spring Boot Test / Selenium
  • Docker / Docker Compose
  • GitHub Pages / Render

5. 開発で得たこと

  • 画面だけでなく、API・DB・外部サービス・デプロイを含めた全体設計。
  • 要件から入力チェック、エラーメッセージ、テストケースへ落とし込む方法。
  • 公開デモで個人情報や秘密情報を扱わないための境界設計。
  • 外部AIを利用する際の根拠限定、失敗時処理、プロンプト防御。

6. 課題と改善案

現在の課題改善案
注文データが再起動で消えるPostgreSQL等へ移行し、保存期間と削除機能を設計する。
認証がない管理者認証と注文履歴のアクセス制御を追加する。
AIの外部依存レート制限、監視、再試行、キャッシュを強化する。
CI/CDが限定的GitHub Actionsでテスト・静的解析・デプロイ確認を自動化する。
商品が1セット商品マスタ、カート、在庫、注文明細へ拡張する。
