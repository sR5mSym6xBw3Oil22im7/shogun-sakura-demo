1. 配置方針

対象配置先配置単位
フロントエンドGitHub Pagesfrontendディレクトリの静的HTML/CSS/JS/画像
バックエンドRender Web ServicebackendをDockerコンテキストとしてビルドしたJavaアプリ
設定Render環境変数APIキー、内部トークン、CORS等

2. バックエンドDockerビルド

  1. maven:3.9.9-eclipse-temurin-21でpom.xmlとsrcをコピーする。
  2. mvn -B -DskipTests packageでJARを生成する。
  3. eclipse-temurin:21-jreへJARだけをコピーする。
  4. 8080をEXPOSEし、java -jar app.jarで起動する。

3. Render設定

項目設定
Service typeWeb Service
RuntimeDocker
Docker contextbackend
Dockerfilebackend/Dockerfile
Health check path/api/health
Auto deploytrue
Build commandDockerfileに委任
Start commandDockerfile CMDに委任

4. GitHub Pages

  • リポジトリの静的配信設定を有効にする。
  • .nojekyllを配置し、そのまま配信する。
  • 公開URLのfrontend/配下をエントリとする。
  • フロントコード内の公開API URLがRenderを指すことを確認する。

5. デプロイ後確認

  1. バックエンドの/api/healthがstatus=okを返す。
  2. トップ画面、画像、CSS、JavaScriptが正常に読み込まれる。
  3. 注文確認からデモ注文が登録できる。
  4. 注文履歴に登録データが表示される。
  5. AI案内が回答または適切な回答不能表示を返す。
  6. ブラウザコンソールにCORS・404・JavaScript例外がない。

6. ロールバック

  • フロント：直前の正常コミットへ戻してGitHub Pagesを再公開する。
  • バックエンド：Renderで直前の正常デプロイを再デプロイする。
  • 環境変数変更が原因の場合は直前値へ戻して再起動する。
  • H2データは再デプロイで消失することを許容する。
