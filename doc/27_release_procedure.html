1. リリース前確認

  1. 対象コミットと版数1.0.0を確認する。
  2. 秘密情報がリポジトリへ含まれていないことを確認する。
  3. GEMINI_API_KEY、MCP_INTERNAL_TOKEN、MCP_BASE_URL、ALLOWED_ORIGINSを準備する。
  4. テスト結果報告書が合格であることを確認する。
  5. 公開URLとAPI URLを確定する。

2. バックエンド公開

  1. Render Web ServiceをDockerランタイムで作成する。
  2. リポジトリを接続し、Docker contextをbackend、Dockerfileをbackend/Dockerfileに設定する。
  3. 環境変数をRenderの管理画面へ設定する。
  4. Health check pathを/api/healthに設定する。
  5. デプロイを実行し、ビルド・起動ログを確認する。
  6. /api/healthが200とstatus=okを返すことを確認する。

3. フロントエンド公開

  1. フロントのAPI_BASE_URLがhttps://shogun-sakura-demo.onrender.comを指すことを確認する。
  2. GitHub Pages対象ブランチへリリースコミットを反映する。
  3. .nojekyllを含めて公開する。
  4. 公開URL https://sr5msym6xbw3oil22im7.github.io/shogun-sakura-demo/frontend/ へアクセスする。
  5. 画面、画像、注文、履歴、チャットを確認する。

4. リリース判定チェック

確認項目判定
トップ画面表示確定
静的資産の404なし確定
ヘルスチェック正常確定
CORSエラーなし確定
デモ注文登録確定
注文履歴表示確定
AI案内の正常／回答不能制御確定
実決済が発生しない確定

5. ロールバック

  1. 障害範囲をフロント、バック、設定に切り分ける。
  2. フロントは直前の正常コミットへrevertする。
  3. バックはRenderの直前正常デプロイへ戻す。
  4. 設定変更は直前値へ戻し、サービスを再起動する。
  5. H2データ消失はデモ仕様として許容する。
  6. 復旧後にヘルスチェックと主要操作を再確認する。
