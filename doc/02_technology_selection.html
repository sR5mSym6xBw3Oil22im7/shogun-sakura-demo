1. 選定方針

学習成果を明確に示すため、フロントエンドはフレームワークに依存しない構成、バックエンドは業務Webアプリで利用例の多いJava/Spring Boot構成とした。公開は静的サイトとAPIを分離する。

2. 採用技術

分類技術採用理由
フロントエンドHTML5セマンティックなページ構造とフォームを標準機能で実装できる。
フロントエンドCSS3高級ギャラリー風の配色、レスポンシブ表示、状態表示を実装できる。
フロントエンドVanilla JavaScript入力検証、画面遷移、Fetch API、チャットUIを基礎技術として示せる。
バックエンドJava 21LTS世代の言語機能と安定した実行環境を利用できる。
バックエンドSpring Boot 3.3.5REST API、Validation、DI、例外処理、JDBCを統合しやすい。
DBH2 Databaseデモ用途でサーバー内に軽量なインメモリDBを構築できる。
DBアクセスSpring JDBCSQLと保存処理を明示し、構造を理解しやすくする。
AIGemini APIサイト本文を根拠とする自然言語回答を実装できる。
AI連携Model Context Protocol SDK 2.0.0サイト本文取得ツールを内部機能として分離できる。
HTML解析jsoup 1.18.3許可したページから表示テキストだけを抽出できる。
テストJUnit / Spring Boot Test / Selenium 4.24.0単体、API、ブラウザ操作の各層をテストできる。
実行環境Docker / Docker Compose開発環境と公開環境の差を抑えられる。
公開GitHub Pages静的フロントエンドをHTTPSで公開できる。
公開Render Web ServiceDocker化したSpring Boot APIを公開し、ヘルスチェックを設定できる。

3. 不採用・保留技術

技術判断
React / Vue画面規模が小さく、基礎的なDOM操作とJavaScript実装を示す目的を優先した。
MySQL / PostgreSQL永続運用を目的としないデモのため、H2を採用した。
認証基盤会員機能を対象外としたため採用しない。
決済API実販売を行わないため採用しない。

4. 技術上の制約

  • H2はプロセス再起動・再デプロイでデータが消失する。
  • Gemini API、MCP内部通信には環境変数が必要である。
  • GitHub Pagesは静的配信のため、バックエンドAPIは別ドメインとなりCORS設定が必要である。
