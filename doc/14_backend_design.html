1. レイヤ構成

レイヤ主要クラス責務
起動ShogunSakuraApplicationSpring Bootアプリケーション起動。
ControllerOrderController / ChatController / HealthControllerHTTP要求受付、Validation、レスポンス返却。
ServiceOrderService / ChatService / SiteContentService業務処理、AI回答、サイト本文取得。
External ClientGeminiGenerateContentClient / SiteKnowledgeMcpClientGemini API・MCPへの通信。
RepositoryOrderRepository / OrderHistoryRepositorySQL実行、注文保存、履歴取得。
DTOCreateOrderRequest等API入出力データ定義。
ConfigCorsConfig / DataSourceConfig / GeminiApiConfigCORS、H2、APIキー設定。
ExceptionGlobalExceptionHandler等入力エラー・予期しないエラーの統一応答。
MCPMcpAuthentication / SiteKnowledgeMcpConfiguration内部ツール公開、認証、Origin制限。

2. 注文処理

  1. OrderControllerがCreateOrderRequestを受け取り、Bean Validationを実行する。
  2. OrderServiceが文字列をtrimし、任意項目の空文字をnullへ変換する。
  3. 商品コードSAKURA_SHOGUN_SET、商品名SHOGUN SAKURA SET、単価4,800円を設定する。
  4. 数量×単価で合計金額を算出する。
  5. OrderRepositoryがPreparedStatementでordersへINSERTする。
  6. 生成IDとcreated_atを取得し、201 CreatedでOrderResponseを返す。

3. 履歴処理

  1. OrderControllerがGET要求を受ける。
  2. OrderHistoryRepositoryがordersをid昇順で取得する。
  3. DB値をOrderHistoryResponseへ変換する。
  4. created_atはAsia/TokyoのOffsetDateTimeとして返す。

4. AI処理

  1. ChatControllerが500文字以内の質問を受ける。
  2. ChatServiceがMCP経由で許可ページ本文を取得する。
  3. MCP失敗時はSiteContentServiceへフォールバックする。
  4. Geminiへサイト本文と質問を送信し、temperature=0で回答を生成する。
  5. 秘密情報を含む回答、空回答、外部障害時はフォールバック判定を行う。

5. 実装原則

  • DIによってクラス間依存を注入する。
  • SQLはRepositoryへ集約する。
  • HTTPステータスとエラー形式をControllerAdviceで統一する。
  • 外部通信は接続・要求タイムアウトを設定する。
  • 秘密値は環境変数から取得する。
