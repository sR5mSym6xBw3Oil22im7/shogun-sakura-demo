System Architecture

システム構成図

GitHub Pages 上の静的フロントエンドが API を呼び出し、Render 上の Spring Boot Web Service が PostgreSQL に注文データを保存・取得する構成です。

System Composition Flow

構成要素のつながり

Browser

利用者

注文入力、確認、注文履歴の閲覧を行う起点です。

GitHub Pages

フロントエンド

index.html、orderConfirmation.html、orderhistory.html と JavaScript を配信します。

  • main.js が入力検証と画面遷移を担当
  • orderConfirmation.js が送信用の架空データを生成
  • orderhistory.js が注文履歴を描画
Render Web Service

Spring Boot API

注文受付、履歴取得、ヘルスチェックを提供するバックエンドです。

  • GET /api/health
  • POST /api/orders
  • GET /api/orders
Render PostgreSQL

orders テーブル

schema.sql で定義された保存先です。 商品コード、商品名、氏名、メール、郵便番号、住所、数量、合計金額、備考、登録日時を保持します。

  • OrderRepository が INSERT を担当
  • OrderHistoryRepository が SELECT を担当

Render のヘルスチェックは /api/health に向いており、CORS 設定は CorsConfig で GitHub Pages とローカル開発環境を許可しています。

Data Flow

データフロー図

注文の入力から保存、注文履歴の取得までを、実際の JavaScript と Spring Boot の処理単位で追えるように整理しています。

Order Submission Flow

注文送信の流れ

Frontend

注文入力

index.html のフォームに氏名、メール、郵便番号、住所、数量、備考を入力します。

main.js

入力検証

main.js が入力値を検証し、数量を sessionStorage に保存して確認画面へ遷移します。

orderConfirmation.js

確認データ生成

orderConfirmation.js が架空データを生成し、表示用の注文内容を描画します。

HTTP POST

注文送信

POST /api/orders に JSON を送信し、CreateOrderRequest として受け取ります。

Backend

保存処理

OrderController から OrderService、OrderRepository を経由して orders テーブルに保存します。

Response

完了表示

保存結果を返したあと、orderConfirmed.html に遷移して完了画面を表示します。

History Retrieval Flow

注文履歴の流れ

orderhistory.html

履歴画面を開く

注文履歴一覧表示ページを開き、一覧テーブルを描画する準備を行います。

orderhistory.js

履歴取得

GET /api/orders を呼び出し、注文一覧の JSON を取得します。

Repository

DB 参照

OrderHistoryRepository が orders テーブルを検索し、履歴レスポンスへ変換します。

Browser

一覧描画

返却されたデータを表形式で描画し、注文ID、氏名、数量、合計金額、登録日時を表示します。

入力データ

フォーム値、数量、備考、履歴一覧の表示条件

中継データ

JSON リクエスト、API 応答、sessionStorage

永続化データ

orders テーブルに保存された注文レコード
